# MelodyClaw 架构设计文档

> 针对 4C16G 无GPU Ubuntu 服务器的完整架构设计（本地CPU推理）

## 1. 系统概述

### 1.1 硬件环境

| 资源 | 配置 | 说明 |
|------|------|------|
| CPU | 4核 | 支持中等规模模型推理 |
| 内存 | 16GB | 足够加载所有AI模型 |
| GPU | 无 | 所有推理在CPU上进行 |
| 存储 | 充足 | 存储模型和音频文件 |

### 1.2 设计原则

1. **完全本地化** - 所有AI模型在本地CPU上推理，无需外部API
2. **成本为零** - 无API调用费用
3. **隐私安全** - 数据完全本地处理，不离开服务器
4. **内存优化** - 分步加载模型，避免内存峰值

## 3. 本地 AI 模型

### 3.1 模型列表

| 功能 | 模型 | 内存占用 | 推理速度 |
|------|------|----------|----------|
| **人声分离** | Demucs htdemucs_ft | ~800MB | 1分钟歌曲 ~1分钟 |
| **歌词对齐** | Silero VAD | ~500MB | 实时 10x+ |
| **音色克隆** | RVC v2 | ~2.5GB | 1分钟音频 ~4分钟 |

### 3.2 内存分配

```
系统预留:        2GB
Demucs:          800MB (人声分离时)
RVC:             2.5GB (音色克隆时)
Silero VAD:      500MB (歌词对齐时)
音频处理缓存:    2GB
余量:            ~8GB
```

**策略**: 模型分步加载，用完释放，避免同时占用过多内存。

### 3.3 处理时间估算（3分钟歌曲）

| 步骤 | 模型 | CPU时间 |
|------|------|---------|
| 人声分离 | Demucs htdemucs_ft | ~1分钟 |
| 歌词对齐 | Silero VAD | ~10秒 |
| 音色克隆 | RVC v2 | ~12分钟 |
| 音频混合 | pydub | ~5秒 |
| **总计** | | **~13分钟** |

## 4. 模型详细说明

### 4.1 人声分离 - Demucs

**选择理由**:
- 分离质量高
- CPU推理可行
- 内存占用适中

**配置**:
```yaml
separator:
  model: htdemucs_ft    # 快速版
  device: cpu
  batch_size: 1
```

**性能**:
- 内存: ~800MB
- 速度: 3分钟歌曲约 1-1.5分钟
- 质量: 4/5

### 4.2 歌词对齐 - Silero VAD

**选择理由**:
- 极轻量
- CPU推理极快
- 无需GPU

**配置**:
```yaml
aligner:
  model: silero_vad
  device: cpu
  min_silence_ms: 300
```

**性能**:
- 内存: ~500MB
- 速度: 实时 10x+
- 准确度: 5/5

### 4.3 音色克隆 - RVC v2

**选择理由**:
- 音质最佳
- 训练数据需求少
- 预训练模型丰富

**配置**:
```yaml
converter:
  model: rvc_v2
  device: cpu
  sample_rate: 32000    # 降低采样率提速
  f0_method: rmvpe      # 快速音高检测
```

**性能**:
- 内存: ~2.5GB (含Hubert)
- 速度: 3分钟歌曲约 12分钟
- 音质: 5/5

## 6. 数据流

### 6.1 歌声克隆完整流程

```
1. 用户上传歌曲 + 歌词
   │
   ▼
2. 后端保存文件，创建任务
   │
   ▼
3. 本地人声分离 (Demucs)
   │ ┌─────────────────────────────┐
   └─│ Demucs htdemucs_ft (CPU)    │
     │ 内存: ~800MB                │
     │ 时间: ~1分钟                │
     └─────────────────────────────┘
   │
   ▼
4. 本地歌词对齐 (Silero VAD)
   │ ┌─────────────────────────────┐
   └─│ Silero VAD (CPU)            │
     │ 内存: ~500MB                │
     │ 时间: ~10秒                 │
     └─────────────────────────────┘
   │
   ▼
5. 音频切片（按歌词句子）
   │
   ▼
6. 用户选择预设音色
   │
   ▼
7. 本地音色克隆 (RVC)
   │ ┌─────────────────────────────┐
   └─│ RVC v2 (CPU)                │
     │ 内存: ~2.5GB                │
     │ 时间: ~12分钟               │
     └─────────────────────────────┘
   │
   ▼
8. 本地音频混合（克隆人声 + 伴奏）
   │
   ▼
9. 返回结果，前端播放
```

## 8. 扩展性考虑

### 8.1 性能优化

1. **模型量化** - 使用 INT8 量化模型（如可用）
2. **多进程** - 利用 4 核 CPU 并行处理
3. **缓存** - 相同文件不重复处理
4. **分步加载** - 模型用完即释放

### 8.2 未来扩展

1. **更多预设音色** - 根据需求添加
2. **自定义音色训练** - 用户上传音频训练
3. **GPU 支持** - 添加 GPU 后大幅提速
4. **批量处理** - 多任务并行

## 9. 本地 vs 外部 API 对比

| 维度 | 外部 API | 本地 CPU |
|------|----------|----------|
| 成本 | ~$0.03/首 | **免费** |
| 速度 | ~3分钟/首 | ~13分钟/首 |
| 隐私 | 数据上传 | **完全本地** |
| 稳定性 | 依赖网络 | **无依赖** |
| 首次部署 | 快 | 需下载模型 |
| 适用场景 | 快速验证 | **生产环境** |

**结论**: 推荐**完全本地化**，成本为零且隐私安全。
