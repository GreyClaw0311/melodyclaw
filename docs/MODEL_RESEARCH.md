# 模型调研与选型文档

| CPU | 4核 | 并行处理能力有限 |

## 2. 人声分离模型

### 2.1 模型对比

| 模型 | 参数量 | 内存占用 | CPU推理速度 | 分离质量 | 推荐度 |
|------|--------|----------|-------------|----------|--------|
| **Demucs htdemucs** | ~300M | ~1.5GB | 1分钟歌曲约 45-60秒 | ⭐⭐⭐⭐⭐ | ⭐ 首选 |
| Demucs htdemucs_ft | ~150M | ~800MB | 1分钟歌曲约 20-30秒 | ⭐⭐⭐⭐ | 快速版 |
| Spleeter 2stems | ~100M | ~500MB | 1分钟歌曲约 15-25秒 | ⭐⭐⭐⭐ | 轻量级 |
| Spleeter 5stems | ~200M | ~1GB | 1分钟歌曲约 30-45秒 | ⭐⭐⭐⭐ | 多轨分离 |
| Open-Unmix | ~50M | ~300MB | 1分钟歌曲约 10-15秒 | ⭐⭐⭐ | 最轻量 |

### 2.2 详细分析

#### Demucs (推荐)

**优点**:
- 分离质量最高
- 支持 2-stem 和 4-stem 模式
- 预训练模型质量好
- 社区活跃，文档完善

**CPU推理**:
- 内存: ~1.5GB (htdemucs)
- 速度: 3分钟歌曲约 2-3分钟 (4核CPU)
- 优化: 使用 `htdemucs_ft` 可提速 2x

**安装**:
```bash
pip install demucs
```

**使用**:
```bash
# 标准
demucs --two-stems=vocals song.mp3

# 快速版
demucs --two-stems=vocals -n htdemucs_ft song.mp3
```

#### Spleeter (备选)

**优点**:
- 轻量级，内存占用低
- CPU推理速度快
- 安装简单

**缺点**:
- 分离质量略低于 Demucs
- 项目维护不活跃

**CPU推理**:
- 内存: ~500MB (2stems)
- 速度: 3分钟歌曲约 1-1.5分钟

#### 推荐选择

| 场景 | 推荐模型 | 理由 |
|------|----------|------|
| 质量优先 | Demucs htdemucs | 分离质量最佳 |
| 速度优先 | Demucs htdemucs_ft | 质量与速度平衡 |
| 内存受限 | Spleeter 2stems | 内存占用最低 |

## 3. 音色克隆模型

### 3.1 模型对比

| 模型 | 参数量 | 内存占用 | CPU推理速度 | 音质 | 推荐度 |
|------|--------|----------|-------------|------|--------|
| **RVC v2** | ~500M | ~2-3GB | 1分钟音频约 3-5分钟 | ⭐⭐⭐⭐⭐ | ⭐ 首选 |
| So-VITS-SVC | ~400M | ~2-3GB | 1分钟音频约 4-6分钟 | ⭐⭐⭐⭐ | 备选 |
| OpenVoice | ~200M | ~1.5GB | 1分钟音频约 2-3分钟 | ⭐⭐⭐ | 快速验证 |
| GPT-SoVITS | ~600M | ~3-4GB | 1分钟音频约 5-8分钟 | ⭐⭐⭐⭐⭐ | 中文优化 |

### 3.2 详细分析

#### RVC v2 (推荐)

**优点**:
- 音质最佳，接近真人
- 训练数据需求少（10分钟起）
- 支持实时变声（GPU），离线推理（CPU）
- 社区活跃，预训练模型丰富

**CPU推理**:
- 内存: ~2-3GB（含 Hubert 模型）
- 速度: 3分钟歌曲约 9-15分钟（4核CPU）
- 优化: 
  - 使用 `rmvpe` 音高检测（比 `crepe` 快）
  - 降低采样率到 32kHz

**安装**:
```bash
pip install fairseq praat-parselmouth pyworld
# RVC 需要从 GitHub 克隆安装
```

**关键依赖**:
- Hubert 模型: ~190MB
- RVC 模型: ~300MB
- 音高检测模型: ~100MB

#### So-VITS-SVC (备选)

**优点**:
- 音质较好
- 支持多说话人

**缺点**:
- 训练需要更多数据
- CPU推理较慢

**CPU推理**:
- 内存: ~2-3GB
- 速度: 3分钟歌曲约 12-18分钟

#### OpenVoice (快速验证)

**优点**:
- 轻量级
- 无需训练，即用
- CPU推理速度快

**缺点**:
- 音质一般
- 音色保真度较低

**CPU推理**:
- 内存: ~1.5GB
- 速度: 3分钟歌曲约 6-9分钟

### 3.3 推荐选择

| 场景 | 推荐模型 | 理由 |
|------|----------|------|
| 质量优先 | RVC v2 | 音质最佳 |
| 中文歌曲 | GPT-SoVITS | 中文优化 |
| 快速验证 | OpenVoice | 速度最快 |

## 6. 优化建议

### 6.1 内存优化

1. **分步加载**: 只在需要时加载模型，用完释放
2. **量化模型**: 使用 INT8 量化版本（如果可用）
3. **批处理优化**: 小批量处理避免内存峰值

### 6.2 速度优化

1. **使用快速版模型**: Demucs `htdemucs_ft`
2. **降低采样率**: RVC 使用 32kHz 而非 48kHz
3. **并行处理**: 利用 4 核 CPU 进行并行处理

### 6.3 推荐配置

```python
# config.yaml
separator:
  model: htdemucs_ft      # 快速版
  device: cpu
  batch_size: 1           # 小批量避免内存峰值

converter:
  model: rvc_v2
  device: cpu
  sample_rate: 32000      # 降低采样率
  f0_method: rmvpe        # 快速音高检测

aligner:
  model: silero_vad
  device: cpu
```

## 7. 完全本地化方案

### 7.1 最终推荐配置

| 功能 | 模型 | 内存 | 时间/首 |
|------|------|------|---------|
| 人声分离 | Demucs htdemucs_ft | 800MB | ~1分钟 |
| 歌词对齐 | Silero VAD | 500MB | ~10秒 |
| 音色克隆 | RVC v2 | 2.5GB | ~12分钟 |
| 音频混合 | pydub | 100MB | ~5秒 |
| **总计** | | **~4GB** | **~13分钟** |

### 7.2 对比外部 API 方案

| 维度 | 外部 API | 本地 CPU |
|------|----------|----------|
| 成本 | ~$0.03/首 | 免费 |
| 速度 | ~3分钟/首 | ~13分钟/首 |
| 隐私 | 数据上传 | 完全本地 |
| 稳定性 | 依赖网络 | 无依赖 |

### 7.3 结论

**推荐使用完全本地化方案**：
- 16GB 内存足够运行所有模型
- 虽然速度较慢，但成本为零
- 数据不离开服务器，隐私有保障
- 无需依赖外部 API
